# Импорт банковских выписок

В разделе **Операции → Импорт выписки** загрузите CSV или XLSX (до 10 МБ, до 50 000 непустых строк данных, 100 колонок). Импорт доступен владельцу, администратору и участнику семьи по праву `finance.write`. Все данные и сохранённые профили доступны только активной семье.

## Как пройти мастер

1. Выберите файл, кодировку CSV, разделитель, номер листа XLSX и строку заголовков. Нажмите **Прочитать файл**. Тип определяется по содержимому. Старый XLS нужно локально сохранить как XLSX/CSV; PDF пока не распознаётся.
2. Проверьте показанные заголовки и примеры. Без BOM читается только строгий UTF-8: для Windows-1251 выберите её явно. Поддерживаются BOM UTF-8 и UTF-16 LE/BE. Нечитаемый текст не сохраняется молча. Автоопределение разделителя может потребовать ручного выбора, особенно при преамбуле перед таблицей.
3. Выберите профиль или **Мастер колонок**. В мастере укажите дату, описание и сумму: подписанная сумма, две колонки приход/расход либо направление + модуль. Для направления задайте значения, означающие приход и расход. У двухколоночной строки оба ненулевых значения запрещены. Суммы со знаком «−», пробелами, NBSP и узкими пробелами поддерживаются; десятичный разделитель выбирается явно. Избыточные дробные знаки не округляются.
4. Укажите формат даты: ISO, DD.MM.YYYY / DD/MM/YYYY или MM/DD/YYYY. Двухзначные годы не поддерживаются: предварительно приведите их к четырёхзначному виду. Типизированные даты Excel читаются с учётом системы 1900/1904; произвольное число не превращается в дату автоматически. Дата проводки при наличии имеет приоритет; обе исходные даты сохраняются.
5. Сопоставьте каждый счёт из файла со своим счётом. Для строк без названия выберите общий счёт. Последние цифры карты — только подсказка, новые счета не создаются. Валюта движения должна совпадать с валютой счёта; исходная валютная покупка — метаданные, автоматической конвертации нет. Начальный остаток счёта должен относиться к началу импортируемой истории, иначе текущий баланс удвоится.
6. При необходимости сохраните настройки чтения и колонок новым профилем семьи. В следующий раз выберите его до чтения файла, затем в списке профилей. Привязка счетов проверяется заново. Если в колонке более 100 уникальных значений, мастер показывает первые 100; остальные несопоставленные счета останутся ошибками в предпросмотре.
7. Проверьте предпросмотр. Есть фильтры **Новые / Дубли / Переводы / Плановые / Ошибки**, массовый пропуск, создание и назначение категории; отображаются по 50 строк, на телефоне — карточки. Общие приходы/расходы показывают движения файла до решений, включая обе стороны переводов и дубли. Это не итог аналитики семьи.
8. Выберите решение для спорных строк. По умолчанию совпадения с ручными операциями (та же сумма на том же счёте в окне ±2 дня) пропускаются. Можно связать их с операцией без создания. Точный повтор файла даёт предупреждение, а перекрывающиеся выгрузки сверяются по мультимножеству fingerprints: две одинаковые покупки законны. Совпадение без стабильного ID можно явно признать отдельной покупкой. Стабильный банковский ID повторно создать нельзя; указывайте в этой колонке только действительно стабильный ID, а не авторизационный код или номер строки.
9. Для подтверждения плановой операции выберите её кандидат: фактические дата/сумма берутся из выписки. Окно дат (по умолчанию ±3 дня) и допуск суммы настраиваются до предпросмотра; допуск хранится в минорных единицах валюты строки. При нескольких кандидатах строка по умолчанию пропускается до ручного выбора. Плановые переводы сопоставляются в одной валюте: две встречные строки подтверждают одну плановую операцию, с датой списания; при отмене восстанавливается исходный план. Односторонняя выписка тоже может подтвердить такой перевод, а следующая сторона предлагается как уже существующая. Используются уже материализованные плановые операции; дальние виртуальные начисления нужно сначала открыть/материализовать в приложении.
10. Для своего перевода выберите **Свой перевод** у обеих встречных строк и проверьте их взаимное сопоставление. Противоположные суммы в одной валюте на разных собственных счетах в окне ±2 дня — только кандидат. Будет создана одна операция `transfer`. Если встречная сторона уже есть в базе, её можно явно преобразовать в перевод или связать с уже существующим переводом. Комиссия остаётся отдельным расходом. По одному слову «СБП» перевод своим не считается. Автоматическое сведение валютных сторон банковской выписки не выполняется; явные переводы из экспорта BestBudget сохраняют обе валютные суммы.
11. Категории предлагаются в порядке: правило семьи → небольшой MCC-словарь стандартных категорий → совпавшее название банковской категории → без категории. Для новой операции без категории выберите её или пропустите строку. **Запомнить для похожих** создаёт правило по подстроке нормализованного описания с приоритетом 100. Дополнительная форма позволяет задать подстроку/RE2 regex, MCC, валюту, диапазон модуля суммы и приоритет (условия через «и»). Правила применяются при новом предпросмотре; выражения без lookaround/обратных ссылок, до 200 символов; до 500 правил семьи. Правило и его версия видны у предложенной категории.
12. При наличии двух и более последовательных остатков по счёту они сверяются с движениями между ними. Первый остаток — точка отсчёта, а не подтверждение начального баланса. Несходящаяся сверка требует отдельного подтверждения. Остатки без дат/семантики «после операции» нельзя назначать этой колонке. Неупорядоченные движения одного дня могут потребовать ручной проверки. Отсутствие контроля отображается явно.
13. Нажмите **Подтвердить импорт → Записать операции**. Вся партия записывается атомарно: ошибка не оставляет частично созданных операций. Повтор подтверждения той же партии возвращает уже записанный результат. Если другая партия была записана после предпросмотра, новые совпадения блокируют запись до проверки. При потере соединения откройте партию в истории и проверьте статус.

Банковские строки `pending`, `rejected` и неизвестного статуса остаются в предпросмотре только для пропуска. Собственный экспорт BestBudget — отдельный доверенный контракт: его планы и пропущенные операции восстанавливаются в исходном статусе, без записи в факт; само расписание CSV не содержит, его нужно создать отдельно. В неизвестном профиле отсутствие статуса требует явного выбора «считать строки без статуса завершёнными». Возврат не определяется автоматически только по знаку: категорию дохода выберите сами. Строки с ошибками нужно исправить в файле/настройках и создать новый предпросмотр либо пропустить. Черновики хранят нормализованные строки, но несохранённые изменения решений в браузере при обновлении страницы сбрасываются.

## Отмена

Откройте партию в истории и нажмите **Отменить импорт**. Удаляются только созданные ею операции с неизменившейся `version`. Подтверждённые плановые операции восстанавливают исходные статус, сумму и дату; преобразованные ручные операции также восстанавливаются. Связанные без изменения ручные операции остаются. Версии продолжают возрастать.

Если хотя бы одна затронутая операция изменена/удалена или связана с другой завершённой партией, отмена целиком отклоняется со списком позиций. Никакого частичного удаления или принудительного отката изменённой истории нет. Это относится и к переводам, собранным из нескольких партий: их нужно разобрать вручную, без автоматического удаления общей операции. После успешной отмены та же выгрузка может быть импортирована заново.

## Форматы и степень подтверждения

Сведения о банковских интерфейсах взяты из [исследования от 23.10.2026](research/bank-integrations-ru.md) и [спецификации форматов](research/statement-formats.md). Реальных банковских образцов в репозитории нет; тесты используют только синтетические данные.

| Источник | Как получить | Статус в BestBudget |
|---|---|---|
| BestBudget CSV v1 | [Скачать шаблон](/api/import/template), заполнить локально | Собственный поддерживаемый контракт |
| Экспорт BestBudget | Операции → экспорт CSV (`/api/export/transactions`) | Поддерживается обратный импорт операций, включая явные переводы с суммой/валютой зачисления; planned/skipped сохраняются без превращения в факт |
| Т-Банк | **[П]** ЛК на компьютере → Операции → период/продукты → Поделиться → формат | **Экспериментальный, проверьте предпросмотр**. Исторический CSV-кандидат с `;`, DD.MM.YYYY, десятичной запятой, `Сумма платежа` / `Валюта платежа`, `OK` + непустая дата проводки. **[Н]** Диалект и окончательность статусов 2026 года. Исторический CSV Альфа-Клик не объявляется текущим профилем |

## BestBudget CSV v1

UTF-8 (BOM допустим), `;`, LF/CRLF, стандартные кавычки с удвоенными `"` и переносами внутри поля. Обязательные заголовки: `account;date;amount;currency;description`; порядок колонок произвольный. Названия нормализуются по регистру и пробелам, неоднозначные повторения не принимаются.

```csv
account;date;amount;currency;description;external_id;status;mcc
DEMO_DEBIT_A;2026-10-20;-450.00;RUB;MAGAZIN PRIMER;;posted;5411
DEMO_DEBIT_A;2026-10-21;50.00;RUB;Рублёвый кэшбэк;;posted;
```

`account` — согласованная локальная подсказка для ручной привязки. `date` — день движения `YYYY-MM-DD`. `amount` — движение по счёту в основных единицах: положительный приход, отрицательный расход, десятичная точка, число знаков по ISO exponent валюты (RUB 2, JPY 0, BHD 3). Ноль не создаёт операцию. Валюта обязательна в каждой строке. Только в этом профиле пустой `status` означает `posted`.

Опционально: `external_id` (стабильный ID), `status` (`posted/pending/rejected`), `mcc` (строка из четырёх цифр), `bank_category`, `booking_date`, `original_amount`, `original_currency`, `balance_after` (остаток после движения). Подсказки `kind_hint` не разрешают автоматический перевод; решение основывается на сопоставленных собственных счетах и явном выборе пользователя.

Экспорт BestBudget использует русские заголовки, десятичную запятую, BOM и CSV-экранирование формул. Новые выгрузки содержат `ID операции`: в той же семье он даёт прямой кандидат «уже есть», в другой семье идентификаторы не раскрывают данные источника. Старые выгрузки без ID также читаются. Профиль восстанавливает знак расходов, явный перевод, статус, исходный текст после экранирования и обе суммы/валюты. Категории привязываются по названию с последующей проверкой. Экспорт не создаёт счета и категории в другой семье; сопоставьте их вручную. В источнике и получателе должны быть согласованы начальные остатки. Старые файлы с буквальным начальным апострофом перед `=+-@` неоднозначны: новая версия экспорта сохраняет такие префиксы обратимо.

## Безопасность файлов

Файл обрабатывается в памяти только во время чтения; оригинал не записывается на диск или в БД. После предпросмотра сохраняются нормализованные строки, raw-описание, происхождение, хеш и решения. Описания не попадают в обычные логи. Upload route проверяет Origin/сессию и ограничивает фактически прочитанный поток; общий лимит server actions не увеличивается.

XLSX проверяется до чтения: не более 40 МБ реально распакованных данных и 1000 ZIP-записей, ограниченные координаты и суммарные области листов, не более 40 МБ значений после разворачивания shared strings, без формул, макросов, вложений, XML entities и внешних ссылок. Формулы не исполняются и даже их кешированные значения не импортируются. Повреждённая/неподдерживаемая книга даёт объяснимый отказ. Защита CSV от формул действует при экспорте; входящий текст формулами не исполняется.

## Как предложить профиль нового банка

Не передавайте логины, пароли, SMS-коды, QR входа и оригиналы с персональными данными. По [протоколу образцов](research/statement-formats.md#7-как-получить-образцы-и-снять-неопределённость) локально обезличьте короткий период с покупкой, приходом, возвратом, переводом и пересечением с другой выгрузкой. Сохраните исходные заголовки, типы ячеек, кодировку, знаки, пустоты, формат дат/сумм и арифметику остатков; реквизиты замените согласованными `DEMO_*`.

В приватном issue опишите банк/продукт, дату/версию интерфейса, путь меню и предложенные форматы. Приложите только проверенную обезличенную копию по согласованному приватному каналу, без настоящих номеров/ссылок/метаданных. Для PDF чёрный прямоугольник не удаляет скрытый текст; PDF сейчас не нужен импортёру. Публичная fixture должна быть заново созданной синтетикой. Профиль принимается после локальной сверки на реальном обезличенном файле, а не по одному логотипу или названию банка.
