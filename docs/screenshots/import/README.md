# Импорт — синтетическая браузерная проверка

Скриншоты из `e2e/imports.spec.ts`, Chromium на production standalone-сборке:

- `import-preview-375.png` — 30 строк карточками, компактный степпер, редактирование через sheet, кнопки без перекрытия FAB; проверяется `document.documentElement.scrollWidth <= innerWidth`.
- `import-preview-desktop.png` — те же 30 строк в таблице: 24 новые, один дубль, две стороны перевода, одна плановая, один ожидающий проводки холд и одна ошибка. Итоги исключают выбранный перевод и пропуски.
- `import-duplicates-desktop.png` — повтор CSV: 28 дублей / уже учтённых строк, один холд и одна ошибка, к записи ноль операций.

Данные полностью синтетические: `owner@e2e.test`, PYATEROCHKA и вымышленные покупки/счета/платежи. Кандидаты готовятся только в изолированной базе Playwright на 54330; настоящий `DATABASE_URL` из окружения не используется. Это проверка UI и собственного формата, не приёмка реальной банковской выгрузки.

Браузерный сценарий проходит мастер колонок, фильтры, выбор строк, массовую смену категории/решения, предложение применить категорию к восьми похожим покупкам, диалог правила, мобильный sheet, commit → повтор/дубли → undo. Дополнительные сценарии проверяют XLSX/Origin и показ 205 строк порциями по 100, без изменения категории невыбранных строк. Холд показан серым статусом «Ожидает», с пояснением в desktop tooltip и мобильном sheet. Проверяется решение «пропустить» по умолчанию и отсутствие проводки после импорта; некорректная дата остаётся ошибкой даже у холда. Старый черновик с прежним общим предупреждением получает актуальное пояснение. Категория подтверждаемой плановой берётся из существующей операции, даже если банковская подсказка отличается.

Воспроизведение: `npx -y pnpm@10.27.0 test:e2e`; изображения появляются в `work/import-*.png`. Порты 3200/54330 должны быть свободны. Для собственного кеша браузера задайте `PLAYWRIGHT_BROWSERS_PATH` в дисковой временной директории и предварительно выполните `pnpm exec playwright install chromium`.
