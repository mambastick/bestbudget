# Матричные e2e-проверки

`npx -y pnpm@10.27.0 test:e2e` собирает production-приложение и запускает standalone-сервер с отдельной PGlite на портах 3200/54330. Каждый запуск начинает с пустой БД. Процессы приложения владельца на 3000/3100/54329 не используются.

В `assets-i18n`, `finance-i18n` и `admin-i18n` каждый вариант ru/en × light/dark × 1280/375 — отдельный тест с лимитом 60 секунд. Seed создаётся в `beforeAll` один раз на спек, авторизация переиспользуется через cookies, браузерный контекст создаётся заново для каждого теста. Проверки переполнения, гидрации и консольных ошибок выполняются в каждом варианте. Сценарии изменения финансовых данных вынесены в отдельные тесты после матрицы.

При падении Playwright перезапускает worker и выполняет `beforeAll` заново: случайный e-mail создаёт нового пользователя и семью. Следующие варианты не зависят от успешного завершения предыдущего. В административной спеке заменяется только тестовая запись доставки с её собственным dedupe key, поскольку список доставок общий для всей установки.

Service Worker в трёх матрицах отключён: его установка в каждом новом контексте не относится к проверкам финансовых экранов и отдельно покрывается PWA-спекой.

В PWA отдельно параметризованы Safari/Chrome и light/dark standalone; `imports` уже состоит из отдельных сценариев и большой матрицы не содержит.

Один worker сохранён по результатам проверки, а не только из-за общих данных. Эксперимент с двумя workers для трёх изолированных матриц после завершения глобальных сценариев упал при seed с SQLSTATE `08P01`: `bind message supplies … parameters, but prepared statement "" requires …`. PGlite — односессионная БД; socket-сервер мультиплексирует клиентов, но не обеспечивает полную семантику независимых PostgreSQL-сессий. Уникальных пользователей и семей недостаточно. Кроме того, acceptance меняет глобальные настройки OIDC и временно блокирует остальных администраторов, а PWA-проверка обновления подменяет общий `sw.js` production-сервера. Для двух workers нужны полноценный PostgreSQL с отдельными сессиями и изоляция глобальных сценариев либо отдельные сервер/БД на worker. Новые `ai-*` спеки не менялись.

Скриншоты матриц, локализации, существующей AI-спеки и PWA (включая `public/screenshots`) обновляются только вручную:

```bash
UPDATE_SCREENSHOTS=1 npx -y pnpm@10.27.0 test:e2e
```

В существующей AI-спеке локаторы ограничены видимым активным чатом: скрытые Activity-деревья предыдущего маршрута не участвуют в проверках. Скриншоты больше не служат случайной паузой между действиями. Новые `ai-*` спеки в эту правку не входят.

В обычном прогоне нет безусловной записи снимков каждой страницы матрицы. Диагностика Playwright и JSON-вложение finance остаются в `work/playwright`; после неуспешного теста сохраняется trace. `E2E_SKIP_BUILD=1` позволяет переиспользовать существующую production-сборку; для сравнения времени нужно одинаковое значение этого параметра до и после.

## Локальный замер 2026-10-23

Один Linux-хост, Node.js 26.8.2, одинаковые Chromium/ENV и один worker. Каждый полный запуск выполнял `next build` и начинал с новой PGlite; `E2E_SKIP_BUILD` не использовался. Время — wall time всей команды `npx -y pnpm@10.27.0 test:e2e --reporter=list,json`, без ожидания освобождения занятых другим агентом портов.

Среднее после изменения — 286,29 с: на 6,78 с (2,3%) быстрее успешного baseline. Все три финальных запуска подряд — без retries, пропусков и flaky. Самый долгий отдельный вариант матрицы — 4,72 с при лимите 60 с. В обычных прогонах файлы docs/public не изменялись. Это локальный замер, время CI пока не измерено.

Первая исходная попытка заняла 290,21 с и завершилась 38 passed / 1 failed: глобальный AI-локатор нашёл две копии чата. Она не использовалась для сравнения успешных полных прогонов. Пробный запуск двух матричных workers упал с `08P01` при seed; поэтому финальная конфигурация оставляет один worker.
